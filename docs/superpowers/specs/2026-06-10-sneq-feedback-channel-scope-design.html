01
Mission

Le gap, deux audiences

La commande du Maître de Forge, transmise en fin de session précédente :

De : Jean · Canal : handoff 2026-06-10 · Objet : le dernier gap

« filling one remaining gap: cli should be able to receive feedback from consumer or we should have a documented way for any consumer to create a gh issue to send feedback/reviews/frictions etc »

Une seule phrase, mais deux populations qui ne peuvent pas emprunter le même chemin. La réponse est en deux moitiés, une par audience.

Audience A
Les consommateurs humains
  • Devs qui installent sneq-engine depuis npm.
  • Savent ouvrir une issue GitHub, encore faut-il leur dire où et comment : le repo n'a aucun dossier .github/ aujourd'hui.
  • Frictions typiques : adapter, install, doc, API.
→ templates d'issues + section README
Audience B
L'agent in-game
  • Le MJ IA qui consomme le CLI en pleine partie.
  • Ne peut pas ouvrir d'issue, et surtout : quand SNEQ ne marche pas, il contourne en silence pour ne pas casser la narration. Zéro visibilité.
  • Le signal le plus précieux est celui qu'il ne rapportera jamais de lui-même : ce qu'il n'a pas appelé.
→ verbe CLI + télémétrie passive
02
Décision

Scope retenu

Le spec Meta Layer (2026-05-25, approuvé) décrit trois capacités. Ce chantier en implémente deux, plus le chemin humain qui n'y figurait pas.

CAP 1
CanonDirective
Lois-monde posées en méta-break, remontée dans prepare-turn. C'est du canon, pas du feedback : cycle de vie à part, hors-sujet pour ce gap. Le design reste intact dans le spec mère.
Différée
CAP 2
FeedbackEntry
Le verbe fire-and-forget report-feedback (outil LLM), le digest feedback, le triage triage-feedback avec cycle de vie OPEN → TRIAGED / PROMOTED / DISMISSED.
Retenue
CAP 3
Télémétrie de couverture
Une ligne ToolCallLogEntry par appel d'outil, capturée au point d'étranglement unique dispatchToolCall, classifiée OK / EMPTY / NO_MATCH / CONTRADICTION / ERROR. Zéro effort agent.
Retenue
NEW
Chemin humain
Templates d'issues GitHub + section README « Feedback » + mise à jour du skill agent. Absent du spec mère, exigé par la mission.
Retenue
Pourquoi 3 avec 2

Sans télémétrie, le digest ne contient que ce que l'agent choisit de dire. Le signal « jamais appelé / contourné en silence » ne peut venir que de la capture passive, et elle est cheap : une fonction pure (classifyOutcome), un try/finally au point d'étranglement, une table. L'écriture est swallowed : elle ne peut jamais casser un appel d'outil.

03
Boucle de croissance

Le canal agent, de bout en bout

Trois commandes nouvelles, un seul outil exposé au LLM. La promotion en issue GitHub reste manuelle, pilotée par l'Intendant : jamais d'auto-promotion (décision verrouillée du spec mère).

report-feedback
L'agent signale ce que la télémétrie ne peut pas inférer : « j'ai contourné l'absence de X ». Fire-and-forget : swallow, retourne {recorded}, invisible au joueur par construction.
▶ outil LLM : sneq__report_feedback
feedback
Le digest : couverture par outil, liste des outils jamais appelés, entrées ouvertes filtrables par --status / --since.
▶ CLI-only (opérateur)
triage-feedback
Le triage : passe une entrée à TRIAGED / PROMOTED / DISMISSED, avec promotedTo = URL de l'issue. Le signal trié ne resurgit pas au digest suivant.
▶ CLI-only (opérateur)

Le rituel « on a des feedbacks ? » devient une session de lecture du digest, synthèse des thèmes, puis promotion des vrais en issues :

intendance@forge : revue hebdomadaire
$ sneq-engine feedback --db ./campagne.db --campaign forge-de-valmure --status open { "coverage": [ { "tool": "sneq__register_fact", "calls": 41, "outcomes": { "OK": 39, "CONTRADICTION": 2 } }, { "tool": "sneq__lookup_entity", "calls": 28, "outcomes": { "OK": 24, "NO_MATCH": 4 } }, { "tool": "sneq__report_feedback", "calls": 3, "outcomes": { "OK": 3 } } ], "neverCalled": ["sneq__suggest_existing", "sneq__validate_narration"], // le signal que l'agent ne donnera jamais "feedback": [ { "id": "fb_7kq2", "origin": "AGENT", "kind": "MISSING", "severity": "MED", "subject": "sneq__add_constraint", "status": "OPEN", "body": "Pas moyen de lier deux entités par une relation temporaire ; contourné avec un fait ETAT." } ] } $ sneq-engine triage-feedback --db ./campagne.db --campaign forge-de-valmure \ --args '{"id":"fb_7kq2","status":"PROMOTED","promotedTo":"https://github.com/JeanDes-Code/sneq-narrative-system/issues/14"}' { "updated": true }

Sémantique verrouillée, héritée du spec mère : la télémétrie et report-feedback sont swallowed (une écriture qui échoue ne casse jamais la partie), la télémétrie ne logge jamais les args bruts (nom d'outil, outcome, durée, détail minimal : pas de prose, pas de PII).

Vigilance

Tests & garde-fous

Layout du spec mère §10, moins les directives, plus la couverture contrat sur les trois adapters. Base actuelle : 235 tests verts, tsc strict.

// Couverture
Domain : test/domain/feedback.test.ts : FeedbackEntry, ToolCallLogEntry, asFeedbackId.
Classification : test/core/telemetry.test.ts : un cas par ligne de la table classifyOutcome (OK / EMPTY / NO_MATCH / CONTRADICTION / ERROR).
Contrat repository : CRUD feedback + tool_call_log + agrégats, exécuté sur sqlite, memory et json via la suite partagée.
Campaign : reportFeedback, triageFeedback, feedbackDigest (coverage + neverCalled + entrées filtrées).
CLI : un fichier unit par commande + les trois commandes dans les patterns e2e et smoke existants.
// Les trois tests qui comptent
Swallow : un recordToolCall qui throw ne fait PAS échouer l'appel d'outil sous-jacent. C'est le test clé du dispatcher.
neverCalled exhaustif : après une campagne où seuls 3 outils advertised sont appelés, le digest liste les 8 autres.
Zéro PII : aucun detail de télémétrie ne contient d'args bruts ni de narration.
07
Expédition

Workflow & ship

Convention maison : un commit par tâche, TDD, et la PR ne se merge que sur ordre explicite du Maître de Forge.

Phase 1
Forge
Branche feat/feedback-channel (déjà ouverte, specs commitées). Plan TDD via writing-plans, puis exécution : domain → repo ×3 + contrat → télémétrie + dispatcher → campaign → outil LLM → CLI → templates / README / skill → e2e + smoke.
Phase 2
Inspection
Suite complète verte + tsc strict + pack-smoke (npm pack + install tmp). Grep privacy avant push : doit être vide. PR ouverte, revue de Jean.
Phase 3
Expédition
Merge sur ton OK explicite. Bump 0.2.0 (additif, zéro breaking), npm publish avec ton OTP. UPGRADING.md : a priori rien à faire côté consommateurs, API additive.
